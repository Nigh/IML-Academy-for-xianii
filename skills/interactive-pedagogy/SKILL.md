# 交互式数学教学

让学生观察现实任务中的变化，或与场景明确对应的数学结果，通过操作检验想法并解释变量关系。借鉴 Brilliant 的主动探索、即时反馈与渐进挑战，交互数量服从学习目标。

## 输入与边界

读取核心任务的已知/目标/限制、场景与数学的映射、读者前置、概念/公式/条件、已有实验与组件接口。没有叙事稿时自行明确这些输入，不强制依赖其他 Skill。场景选择与开场准入属于叙事设计；本 Skill 负责将已明确的任务落实为操作、反馈和理解证据。若输入只有概念名称或装饰性故事，先补齐任务与对应关系再设计交互；抽象内容可使用有理由的具体数学任务，不强造现实类比。本 Skill 可整目录复制到任意技术栈的项目；实现遵守当地组件、状态、无障碍与测试规范。

只设计时输出交互规格，不改课程；实现时只改授权范围。先检查现有组件的真实能力，不把计划、展示型控件或演示截图当作已有交互。

## 项目依赖门禁

执行前读取当地项目的 Skills 前置要求。本项目编写面向学生的课程内容时，必须先核实 math-storytelling、interactive-pedagogy、humanizer-zh 和 ui-ux-pro-max 的实际入口及所需资源；使用后两者分别润色中文和审阅课程 UX。任一缺失、不可读或不完整，暂停内容编写并要求用户安装或修复，复查成功后继续，不得降级替代。只读审查、Skills/规范/工具等非课程内容修改不受限制。移植到其他项目时遵守当地依赖要求，不把本机路径作为前提。

## 为每个关键概念设计探索

设计或审查交互前，必须读取 [现实反馈规格与示例](references/task-feedback.md)，为每个交互填写六问规格卡。交互必须明确模拟对象、可控变量、变化结果、观察关系、概念意义和新条件检验；反例与迁移按下方规则执行。

关键知识发现优先采用：**预测结果 → 调整变量 → 观察结果 → 比较差异 → 总结规律 → 应用到新条件**。接受一次选择、数值或理由，再让学生操作验证；并非每次操作都须完整走六步，自由探索仍须有明确目标与主动推理机会。通过局部提交或主动“查看解释”延迟揭示关键答案，不靠折叠已经露出的结论制造悬念，也不强制每次拖动都先答题。

提示按需递进：“看哪里 → 比较什么 → 怎样推理 → 完整解释”。先给支持继续思考的信息，再在学生尝试或主动请求后展示答案。使用短任务说明与局部提示，让操作自身易懂；不能要求读完说明书才知道拖什么。

## 按内容选择最少够用的交互

- 几何：拖点/角度并观察约束；提供键盘或数值输入等价路径。
- 函数：改变参数，对照图像、取值及变化量；说明固定量与坐标尺度。
- 线性代数：操作向量、矩阵、空间变换；区分对象变化与坐标表示变化。
- 概率：改变分布、运行实验，对照理论和经验结果；标明 seed、样本数和波动，有限实验不能证明定理。
- 微积分：调区间或步长，观察极限与近似误差；有限精度不等于真正取到极限。
- 优化：改变约束、初值或策略，比较轨迹、目标值与失败条件；公平比较时固定其他条件。

不必使用全部类型。每课至少两种有意义的探索场景和两个误区/限制；同一现实任务下的正常与边界条件可以构成不同探索场景，不必增加领域背景。纯本地实验按项目明确豁免，在本地操作中保留预测、观察和反馈目标。

## 反例与迁移检查

先把原始任务中的变量关系讲透，再逐步更换参数、输入、约束，引入边界或看似相似但结论不同的情况。每个关键概念形成后，至少用一个新条件检验认识：让学生先预测、操作或选方法，再比较新旧结果并解释规律能否沿用。反馈指出成立条件如何保留或被破坏；不能只反馈“正确/错误”。

至少一个迁移挑战改变条件、表示或任务，要求判断适用范围、选择方法并解释理由，不能只换数字照套公式。反例必须区分一种具体误解；避免一开始堆叠多个复杂案例。有限操作不能证明一般规律，推导与证明责任交回叙事设计；模型关系不直接等于真实系统规律。

## 实现与验收

数学参数是状态源，图形与读数由同一计算结果派生；数学计算留在独立纯函数。参数变化后清理失效轨迹、预测反馈及运行状态，复位恢复参数与随机种子；保留合理的用户探索自由。

复用已有输入、图表、主题与反馈组件。每个控制项必须对应一个数学问题；移除不影响认识的动画或控件。输入有真实标签、错误说明和键盘路径，图表有轴/单位/图例、非颜色区分和文字结论；兼顾触屏、缩放、窄屏和 reduced motion。限制点数、采样和迭代；隐藏页暂停，卸载清理。

交付规格卡、组件复用/缺口清单和验收证据。重要数值计算测试解析值或不变量、边界、非法输入和容差；交互验证参数到结果的一致性、预测先于解释、针对性反馈、提示、重试及复位。记录实际主题/移动端/键盘检查，未执行的检查明确标记。拖过滑块或答对选择题不自动等于理解。
