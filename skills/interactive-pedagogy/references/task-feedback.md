# 现实任务的交互反馈

设计或审查交互时必读。本文负责操作与反馈规格，不另设开场场景选择体系；先确认任务及其数学对应，再填写规格卡。

## 操作对象准入检查（重要交互实现前强制）

在作者规格卡中逐项回答并附简短依据，不向学生展示此清单：

1. 学生正在操作什么对象？
2. 这个对象在现实中意味着什么？
3. 学生能否理解该动作的物理或实际含义？
4. 结果是否可观察且符合对象和模型的含义？若反直觉，能否通过对照解释原因，而非改动模型迎合直觉？
5. 学生能否预测结果？无法自然预测时，是否仍有明确观察目标？
6. 动作与目标数学概念有什么直接联系？
7. 是否存在比坐标系更直观的表达？
8. 同步显示现实对象与数学图形，是否有助理解关键原理？
9. 是否引入了与学习目标无关的操作复杂度？

第 2、3、6 项不能清楚回答，必须重设计。第 7 项有明显更直观的方案，必须优先采用；第 8 项有助理解时，必须评估联动视图并记录采用或不采用的理由。第 9 项暴露无关负担时删减动作或模型细节；第 4 项不可观察时补反馈。采用 D 类数学任务时，第 2、3 项解释具体对象、合法操作及其数学意义，不编造物理对应；同样检查第 6 项。保留这一例外不等于免审。

## 不合格的现实包装

验收实际操作路径，而不只看页面用了什么名词或插图。以下情况不通过：讲电机却只拖抽象函数曲线，讲机器人却只拖坐标点，讲电路却只调没有物理含义的参数，讲抽样却只看静态分布；或现实插图与动作无关、所有实际推理仍依赖抽象坐标系。

修正时先让控制作用于任务对象，并显示有意义的动作或读数，再用数学视图解释。例如带单位的“采样窗口”控制联动电机测量仪表与速度曲线可以合格；仅把抽象滑块改名或在曲线旁摆一张电机图不合格。滑块、数值输入和按钮仍可作为对象的控制方式，不要求仿制真实旋钮，也不能牺牲键盘路径。

## 六问规格卡（每个交互必填）

每个交互必须回答以下六问，并把预测与数学条件写进同一张规格卡：

| 问题               | 必须可落实的信息                                                                                                                     |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| 学生要发现什么？   | 明确正在模拟的现实任务或具体数学对象、与本课概念的对应、要观察的关系或不变量及预测问题                                               |
| 能操作什么？       | 对象与实际动作、所选 A–D 方案及理由；可控制量对应哪些数学变量，固定什么；标明范围、单位、步长/精度、约束、默认值、复位与非法输入策略 |
| 操作后观察什么？   | 变量改变后哪些任务结果变化、重点比较什么；同步展示图形、数值、中间量和文字；标明解析/采样/预计算及尺度变化                           |
| 为什么有助理解？   | 哪个对照区分哪些解释；模型内的受控变量关系不能外推成现实因果结论                                                                     |
| 错误认识如何反馈？ | 具体错误 → 对应观察或反例 → 修正理由 → 再试入口；区分输入无效与概念误解                                                              |
| 何时可以继续？     | 用哪些新参数/输入/约束检验刚形成的认识，能作出何种预测或解释，以及如何重试/主动查看解释；不擅自添加强制通关或持久化门禁              |

## 现实反馈的选择

优先让操作改变任务中的量，并显示可解释的任务结果；以下是候选方式，不是每课必做的控件清单：

| 操作与反馈                                           | 必须看清的关系或边界                                                            |
| ---------------------------------------------------- | ------------------------------------------------------------------------------- |
| 改变电阻值，观察分压结果                             | 输入电压及负载假设固定时，电阻比怎样影响输出；理想模型不代表实测。              |
| 改变位置测量的时间窗口，观察平均速度                 | 同一段运动中窗口、位移与平均速度的关系；更短窗口可能放大测量噪声。              |
| 调整二维运动平台两路位移指令，观察平台终点与向量合成 | 各动作对应哪条向量、终点怎样改变；固定坐标与比例，保留抵消等退化结果。          |
| 改变传感器噪声并执行采样，观察仪表读数、样本与分布   | 固定真实量与基础随机样本时，噪声参数怎样影响读数；标明分布假设、seed 与样本数。 |
| 改变采样率，比较连续模型与离散采样                   | 采样点为何可能掩盖信号变化；解释信号及采样含义，不能把插值曲线当实测真值。      |
| 调整约束，观察可行解和最优解                         | 哪些解被排除、目标怎样变化；包括无可行解或最优解不唯一的适用情形。              |

不熟悉的术语须用足以开始操作的短说明解释。界面必须说明模拟对象、可控变量、变化结果、观察重点、概念意义与新条件检验；不把完整作者规格表塞给学生，也不把滑块、图或动画本身当作教学成果。

其他可选对象包括 RC 充放电电路、齿轮和电阻抽样实验台：改变电容时显示电压表与充放电进度并联动曲线；改变齿轮比时显示输入/输出转动及转速，涉及力矩时说明理想无损、准稳态等适用假设；从电阻批次中选择或随机抽取样本时显示测量记录、均值与离散程度，区分主动挑选与随机抽样，不能把有偏选择当作总体估计。电路元件标值、转轴位置、动作方向及仪表量必须一致，充放电更快不等于最终电压更高。

## 表示与性能选择（实现前必读）

- 优先复用项目已有 Svelte 组件与设计系统；只表示目标所需的量和关系，简化模型不等于完整物理仿真。
- SVG 适合电路、仪表、机械示意和简单运动；Canvas 适合大量动态对象、粒子、实时数据及复杂绘制；CSS 适合简单旋转、位移和状态过渡。选择取决于对象数量和绘制需要，不要求每课使用所有技术。
- Three.js 或其他 3D 技术仅在三维姿态、空间关系或遮挡不可由更简单视图清楚说明时考虑；不为装饰增加重型依赖。
- 需要约 60 Hz 更新时，区分控件状态、数学计算与绘制：同一帧使用同一状态快照，不在每帧重复昂贵计算或让大范围界面响应更新；按目标帧预算观察耗时，必要时缓存不变量、限制对象数或降低非关键读数的刷新频率。视觉帧率不等于物理积分步长，不能为追求流畅改变模型结果；不强制所有交互达到 60 Hz。
