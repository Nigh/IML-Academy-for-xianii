# 开场准入与场景映射

设计或审查开场时必读。场景选择优先级与 A–F 教学流程由 SKILL.md 规定；本文件提供内部准入、对应关系和选题对照，不是学生讲义。

## 开场问题准入检查（编写前强制）

在内部逐项记录判断与简短依据，不把清单作为学生作业：

1. 能否用不依赖本节知识的日常语言讲清场景？
2. 学生是否知道自己要解决什么问题？
3. 已知条件、目标与限制是否明确到足以开始尝试？
4. 学生能否用已有知识对结果作初步预测？预测可以不准确。
5. 本节知识是否确实改善任务的求解、表达、精度或推广，而非装饰？不要求它是唯一解法。
6. 是否有明显更直观、更熟悉或更容易观察的替代场景？
7. 是否避免了不必要的领域前提，必要术语是否已解释？

第 1、2、5 项任一不通过，必须重设计开场；第 6 项发现明显更好的替代方案，必须采用。第 7 项不通过，必须删减领域负担或补充必要解释。第 3、4 项缺失时，补齐条件或可预测过程后重查，不带着缺项开始编写。选择 C 时同样检查，不以“抽象内容”为由豁免。

## 场景与数学的映射（设计要求）

设计时必须维护相关元素的对应关系；不要求每课向学生机械展示完整表格，但关键量在引入公式时必须解释：

| 场景中的元素       | 数学中的对应对象     |
| ------------------ | -------------------- |
| 可控制的物理量     | 自变量或控制变量     |
| 观察到的结果       | 因变量或观测量       |
| 已知条件           | 初始条件、约束或参数 |
| 需要计算的结果     | 数学目标             |
| 现实中的限制       | 数学模型的适用条件   |
| 测量误差或模型误差 | 不确定性与近似误差   |

删去无法直接映射且无助于任务的细节；相关但模型未覆盖的真实影响，应明确标为简化或局限，不能暗示模型已经解释它。C 类入口则维护具体数学对象、操作与一般定义的对应关系。

交接交互设计时，为相关量补充可操作的对象、动作与可见结果。例如机器人坐标任务应串起“绕标明的轴旋转机身 → 固定世界目标在局部视图中的坐标改变 → 对照世界/局部坐标 → 引入旋转矩阵与平移 → 再旋转并验证预测”。先明确主动变换还是更换坐标表示、哪个对象固定，不能把两种变化混用。若任务只能靠拖坐标点推进，而机身插图与操作无关，须回到映射重新设计；无需增加写实模型。

## 选题对照

选题示例仅用于判断设计，不要求复用：

| 抽象开场（不通过）       | 先建立任务（候选，仍须准入检查）                                                                                                                                             |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 如何理解向量的线性组合？ | 二维云台的两个电机分别沿两个固定方向移动镜头；已知各自的单位位移，怎样组合动作到达指定位置？                                                                                 |
| 什么是矩阵变换？         | 摄像头给出了目标相对自身的位置；已知它相对机器人底盘的朝向和安装位置，怎样计算目标相对底盘的位置？先画清坐标轴；平移需单独相加或使用已解释的齐次坐标，不能说成普通线性变换。 |
| 如何理解概率分布？       | 一批标称 10 kΩ 的电阻测量值有偏差；给定重复测量记录与允许范围，怎样判断偏差是否异常、估计落在范围内的概率？区分器件差异和测量误差，不预设分布形状。                          |
