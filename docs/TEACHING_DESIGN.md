# 课程教学设计质量规范

本规范补充 [LESSON_SPEC](LESSON_SPEC.md)，适用于今后的课程设计与修订，不表示既有课程已经重新验收。LESSON_SPEC 仍拥有教学验收标准，任务卡增加本课要求；本规范将问题驱动、主动探索与迁移要求落实为审阅证据。运行时 schema 不承担教学质量证明。文件所有权、分支和交付遵循 [AGENTS](../AGENTS.md) 与 [CONTRIBUTING](CONTRIBUTING.md)。

## 必需 Skills

课程内容编写前必须按 [Skills 前置检查](TEACHING_SKILLS.md#课程内容编写前的必需检查) 核实四个必需 Skills。使用 math-storytelling 设计叙事、interactive-pedagogy 设计探索、ui-ux-pro-max 审阅课程 UX、humanizer-zh 润色中文并复核数学含义。缺失或不可用时必须要求用户安装或修复后才能继续编写，不允许降级替代。只读审查及其他非课程内容修改不受限制。

## 样板先行与人工责任

M01-002 已经用户实际试用，并在本会话明确评价为“已达到及格水平”，认可基线为 `6d767aa`。它是当前最低可用的交互课程参照，不代表优秀终稿、所有教学类型的模板或整个 M01 已通过。用户本次只授权按同样要求重构 M01-001；其余课程不自动进入批量改造或发布。

模型负责提出候选方案、初稿、实现与技术验证；人类负责确认教学主线、核心实验原型和最终使用体验。另一个模型可以审数学与反例，不能代替人工验收。样板以实际课程和可追溯审阅为参照，不复制相同故事、章节数或布局到所有课程。

实现前提交一页设计稿：学生的具体任务、需要发现的关系、操作对象与反馈位置、理解证据。附核心实验桌面线框及主要标题/一小段正文，明确已学与新增边界、视口及视觉语义。作者清单仅作自查，不得自行宣布“全部满足”即进入样板实现。样板须取得用户对该设计稿的明确认可；实现后若主线或核心操作改变，重新确认这些改变。普通生产课沿用已批准样板的原则，不逐段审批。

样板最终验收由人类按完整任务试用：找到参数、预测、修改、观察、解释、改变条件再验证。记录试用者的前置知识、实际卡点、误解、返工及复验结果；没有合适读者试用时记录缺口，不能宣布样板通过。无需收集个人身份资料或增加学习遥测。推广前，用户确认哪些样板已通过、各自适用何种教学类型及哪些问题仍未解决。

### 已认可基线的可复用要求

- 先用熟悉的实际对象建立任务，标题直接说明对象与动作；不制造加减法等基础操作的理解障碍，不把作者流程或悬念当标题。中文按完整操作路径通读，不能只替换几个“AI 词”。
- 核心对象、控制、执行和主要结果放在同一桌面工作区。一张图能解释的关系不用两张分离图；正文与公式使用桌面内容宽度，不恢复统一的 70ch 上限。继续排除窄屏、竖屏验收。
- 入门位移用有单位的整数加减按钮，分量范围 [−5,5]；若有地图预测，吸附到合法整数点并提供键盘等价操作。其他模型按其实际量纲与精度选择控件，不把这个整数范围推广到概率、损失或物理参数。
- 明确区分参数计划、运动中、已完成与对照状态。位移箭头在对应移动完成后出现；改参、复位或切换任务取消旧运动并清理失效的箭头、终点和反馈，不能只把对象搬回起点。换坐标表示等操作可保留同一对象仍有效的已完成参考，须说明对象没动，不能把它当作一次新执行。
- 入门移动按每段 1 秒匀速显示，减少动态效果时直接完成；隐藏页面停止、卸载清理。换坐标表示不能移动实际对象。其他课程的算法播放与物理时间按模型定义，不机械复制 1 秒。
- 核心数学关系必须通过可操作的对照明确表达。M01-002 用“先走两段，再沿合向量走一次”说明共同终点，同时区分路程与用时；后续课程选择自己的关系与对照，不照搬同一故事和按钮。
- 验证完整状态转换：开始、运行、完成、改参、重试、复位、退化情况和中断。截图须有数学意义，动画测试同时采样位置与可见图形，不能在跨过完成边界后误判运行中状态。

M01-001 可按本次授权直接实现上述基线内的课程设计，最终仍交用户试用；保持 draft，直到用户另行确认发布。若提出超出基线或本课目标的新教学主线，再提交设计确认。此处的会话认可不代替 CONTRIBUTING 中绑定 PR 当前提交的人工门禁。

## 数学正确性

- 公式、推导和结论逐步成立，首次出现定义符号、维度、单位、取值域、假设与适用条件，遵循 [NOTATION](NOTATION.md)。公式使用 KaTeX；不能把图片中的公式作为唯一表达。
- 明确区分数学事实、待证猜想、直觉解释、严格证明、近似方法与经验统计。可视化用来提出或检验猜想；一般结论需要论证或条件明确的定理引用。
- 展示必要推导和至少一个可核查的简单例子；近似说明误差来源，采样说明算法、seed、样本数与局限。不得编造训练、GPU 或硬件结果。
- 重要计算用独立纯 TypeScript 函数，测试解析答案/不变量、退化边界、非法输入和浮点容差；不以截图或实现镜像测试代替数学核查。

## 教学质量

每课有一个读者能理解且值得探索的核心问题；每个新概念说明为什么需要它。优先从简单问题、几何关系或自然工程/ML 任务进入，不强造生活故事。数学本身的问题可作为入口，同时保留任务卡要求的应用案例。先建立足够直觉，再给形式化表达；直觉无法覆盖的地方补逻辑论证。

用 [math-storytelling](../skills/math-storytelling/SKILL.md) 输出“已学 → 新增 → 用途”和灵活叙事链；用 [interactive-pedagogy](../skills/interactive-pedagogy/SKILL.md) 将关键概念落实为预测、操作、观察与解释。不能靠长篇文字完成主要教学，也不能靠控件数量证明有教学价值。

审阅需找到具体证据：

| 要求               | 验收证据                                                                         |
| ------------------ | -------------------------------------------------------------------------------- |
| 关键概念有主动探索 | 学生预测什么、改变什么、根据何种对照解释结果；纯本地课按任务卡在本地完成         |
| 至少两个探索场景   | 正常与边界/反直觉等场景有不同观察目的，默认值、预设及复位可读                    |
| 至少两个误区或限制 | 错误想法、可区分的反例及原因，错误选项有针对性解释                               |
| 至少一个迁移挑战   | 改变条件、表示或任务，学生须选择方法或判断适用性并解释；附解题要点，可计入理解题 |
| 2–4 道理解题       | 预测、条件、公式含义或应用；解释先于答案揭示的学习机会不被正文提前破坏           |
| 3–5 条总结         | 回答开头的问题，相关链接来自已注册课程                                           |

继续学习的条件是可观察的理解证据，不擅自改变平台“用户确认完成”的协议或强制满分。缺少前置知识时补必要说明或报告规划缺口，不偷偷改课程 DAG。

## 文案质量

中文自然、准确、简洁，英文技术术语保持一致。每段承担一个教学作用，说明具体对象、操作与理由。删除空泛鼓励、夸张修辞、固定悬念、机械排比和反复宣告“重要”；幽默不干扰含义。不照搬知名作者口吻或平台文案。

标题直接说明本节对象、动作或关系，脱离上下文也应可检索。“接上已有知识”“回到数学定义”等作者流程标签不能代替内容标题。提问须来自任务中的真实疑问，不把普通经验包装成反直觉悬念。不机械禁用某个句式；若连续用“不是……而是……”制造并不存在的对立，重写推理与段落，而非换同义词。

通读时检查对象名称是否一致、主语是否明确、每段是否帮助下一步操作或推理。领域背景、实现免责声明和作者检查项不塞进主要学习路径；必要模型条件就近简述，其余按需展开。自然文案不能以牺牲数学条件换取流畅。

润色保留否定、量词、条件和结论强度；“可能”不能改成“必然”，“近似”不能改成“相等”。公式、代码、符号和链接不作为普通文案改写。逐项比对润色前后数学含义。

## 技术质量

保持 Svelte 5 runes、严格 TypeScript 和冻结的 contract v1。遵循 [COMPONENTS](COMPONENTS.md) 与 [INTERACTIVE_GUIDE](INTERACTIVE_GUIDE.md)，使用已有语义主题 tokens，复用真实组件接口。以课程状态与 `$derived` 驱动同一数学结果、图形和文本，不维护彼此独立的图形真值。

必须验证有效/无效输入、参数切换、反馈失效清理、复位及有界计算；动画仅表达必要过程，支持单步、暂停、隐藏暂停和卸载清理。连续交互不得阻塞主线程，按实际点数与设备观察响应，发现性能问题再采用必要的节流或计算优化。

横屏桌面、缩放及视觉语义统一按 LESSON_SPEC §4 验收。项目不提供窄屏、竖屏适配，不安排窄屏阅读或降级测试；建议 720p 及以上横屏使用。检查桌面亮暗主题、高 DPI、键盘、可见焦点与 reduced motion。拖拽有等价数值输入；不得用独立缩放误导比较。

## 交付判定

按 [优化流程](LESSON_OPTIMIZATION.md) 记录每项“通过/失败/未运行/不适用”及理由。运行项目要求的类型、lint、格式、课程校验、测试与构建；涉及浏览器的变更执行 e2e，并附实际截图或操作证据。工具通过后仍须人工审阅数学与教学。不得把本规范或 Skill 创建完成写成既有课程优化完成。

以下任一情况阻止教学验收，不因测试通过豁免：

- 在声明支持的桌面视口、100% 缩放下，完成核心参数调整必须离开主要结果再滚动返回；附属说明可以滚动，核心操作与反馈不应分离。
- 同类对象的线型或形状含义不一致，必须背图例才能分辨实际路径、辅助构造和合位移。
- 必须读完长说明才知道操作什么，或场景只存在于插图与开场，实际操作没有对应关系。
- 标题靠虚假悬念或作者流程组织，正文反复制造无必要的对立，读者无法说清具体对象与动作。
- 试用者调对了结果，却无法解释目标关系或迁移条件；应定位设计缺口并复验，不能以“操作完成”代替理解。

验收记录须区分作者自查、自动检查、模型审阅和人类试用；附版本、视口、任务步骤及证据位置。人工确认的落地方式见 CONTRIBUTING。仅增加规范、清单或 CI 不代表已提升任何既有课程的教学质量。
