# 单节课程优化流程

开始前确认课程 ID、读者、授权文件范围和交付方式。按 [质量规范](TEACHING_DESIGN.md) 和 LESSON_SPEC 验收；只要求审查时完成相应设计输出，不自动实施。以下阶段是工作流程，不规定课程页面的章节形状。衔接及外部 Skills 见 [协作说明](TEACHING_SKILLS.md)。

本轮采用样板先行：先做 M01-002，再由用户选定少量不同类型样板；用户认可前不推广生产。按 TEACHING_DESIGN 的人工责任执行，不把每阶段表格直接变成学生页面。当前工作只更新规范和工具，不代表 M01-002 已重构或成为样板。

样板在阶段 2 结束时增加一次明确的人工设计确认：一页任务/关系/操作反馈/理解证据，加桌面线框、视觉编码和代表性文案。取得认可后再实现；这项确认不由作者或另一个模型代签。最终需目标读者完整试用与人工接受；用户明确批准样板及推广范围后，才进入生产。

M01-002 已确认输入：用户认为向量加减法本身没有理解障碍，重构重点是直观例子和连续操作，不人为制造认知困难或悬念。可借鉴 Brilliant 的短任务、操作反馈和渐进探索，不复制其内容或暗示已访问付费课程。用户会亲自操作并反馈；最终记录真实反馈，不预先宣告试用通过。课程实现仍须先确认设计稿。

| 阶段                  | 输入                                                                                                            | 输出                                                                                       | 完成标准                                                                                                                  |
| --------------------- | --------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| 1. 审查内容与数学结构 | AGENTS、ARCHITECTURE、LESSON_SPEC、任务卡、NOTATION、组件文档、指定课正文/定义/计算/测试；本地课另读 LOCAL_LABS | 核心问题、已学/新增/用途、公式与条件清单、具体位置的问题及优先级、现有组件复用表、授权范围 | 每个主要问题有内容或操作证据；区分教学缺口、数学错误、界面问题；记录 ready 的实际内容与测验差距，不泛读其他课程           |
| 2. 重设计问题驱动路径 | 审查结果、目标、前置边界；调用 math-storytelling                                                                | 灵活叙事阶段表、简单到一般的推导、证明责任、两场景/两误区、迁移挑战与答案要点              | 每个新增概念有动机；每阶段回答已知/疑问/下一步/观察；没有未解释的核心前提，也没有提前泄露预测答案                         |
| 3. 实现探索与反馈     | 叙事稿、interactive-pedagogy、真实组件 API 与现有测试                                                           | 六问交互规格卡、最小课内实现、纯函数数学测试和组件测试；使用 ui-ux-pro-max 做定向 UX 审阅  | 操作改变真实数学对象；图形/数值一致；预测后验证；错误反馈针对误解；提示逐层展开、可重试和复位；键盘等价；没有越权共享改动 |
| 4. 润色、测试、验收   | 实现、检查清单；必须调用 humanizer-zh                                                                           | 自然中文定稿、数学复核记录、测试结果、截图/操作证据、修改文件及遗留问题                    | 2–4 题/3–5 总结及已注册链接齐全；迁移挑战要求解释；所有必要检查通过或诚实报告阻塞；不以结构通过替代教学审阅               |

阶段间由证据推进：阶段 2 暴露前置缺口可回阶段 1；阶段 3 的组件限制可回阶段 2 调整探索方式。除样板设计确认与最终验收外，不为每段正文增设批准流程。超出授权范围时先完成范围内独立工作并报告缺口。

## 课程编写前的 Skills 门禁

在阶段 1 开始时，按 [必需检查](TEACHING_SKILLS.md#课程内容编写前的必需检查) 核实四个必需 Skills 的实际入口与所需资源；新环境必须重新核实。缺失时可继续只读审查或其他非内容修改，但不得进入课程内容编写，必须要求用户安装或修复并复查后继续。

## 实现前的组件核对

- 参数：NumericInput、ParameterSlider、PresetSelector；容器：InteractivePanel。
- 视觉对象：VectorDiagram、MatrixView、Plot2D、DistributionPlot、HistogramPlot、ContourPlot；概率与向量基础计算已在 `src/lib/math`，梯度下降在 `src/lib/simulations`。
- 过程：StepByStep 只展示解释，不计算；SimulationControls 只推进步号，不拥有数学状态。
- 教学：FormulaBlock、DefinitionBlock、ExperimentGuide、CommonMistakes、LessonSummary。
- 理解检查：KnowledgeCheck 是主动展开答案的 details，不能收集预测或判题；正式 QuizBlock 由 Shell 按 `lesson.ts` 配置，提交后反馈所选项解释。需要课中提交预测/分层提示时，可在授权课目录用现有输入和本地状态组合，不能假设已有自适应教学引擎。
- Shell 已有标题、目标、前置、测验、进度与导航，不在正文重复实现，也不另建完成状态系统。

表中能力以执行时的源码与 COMPONENTS 为准。新课只能写课内/实验目录；公共能力需求记录到交付报告，不能顺手改接口。

## 验证记录

记录课程 ID、版本、公式的解析核对/反例/容差、完整任务操作与解释、默认/预设/复位图形、亮暗主题、1280×720 与 1920×1080 横屏桌面、桌面 200% 缩放、键盘、链接与范围。窄屏、竖屏完全不在适配与测试范围内，不保留 320px 阅读或降级验收。作者自查、自动结果、模型审阅、人工试用分开记录；不得将自查结论冒充学生理解。代码变更执行：

```bash
pnpm check
pnpm lint
pnpm format:check
pnpm validate:curriculum
pnpm validate:lessons
pnpm test
pnpm build
pnpm test:e2e
```

e2e 用于浏览器影响变更；按 CONTRIBUTING 配置 `LESSON_SELECTION` 验证指定课程，默认 e2e 只跑固定回归。修改生成源时还需相应生成与一致性检查。失败必须列出原因与影响；未跑的设备/GPU/CI 不写通过。通过本地检查不代表已合并或部署。

记录完整任务：试用者能否找到控制项、预测、修改并就地观察结果、解释关系、在新条件下验证。写实际卡点与复验结果，不只附空白表或成功截图。PR 人工审阅需绑定当前提交，具体方式见 CONTRIBUTING。CI 不检测“AI 味”，不以关键词黑名单、截图存在或勾选数判断教学合格。

## 可复制的优化提示词

替换尖括号中的值后使用；只填一节已注册课程。

```text
请优化课程 <LESSON_ID>，目标读者为 <读者与正式前置>，核心学习目标为 <目标>。
允许修改范围：<明确目录/文件>。交付模式：<只审查设计 / 实现并验证>。

先读 AGENTS.md、docs/ARCHITECTURE.md、docs/LESSON_SPEC.md、对应任务卡、
docs/COMPONENTS.md、docs/NOTATION.md、docs/TEACHING_DESIGN.md，
本地实验另读 docs/LOCAL_LABS.md；只读取指定课程实现与直接所需基础代码。
按 docs/LESSON_OPTIMIZATION.md 的四阶段执行，输出每阶段证据并推进授权范围内工作。
样板先提交一页设计稿、桌面线框、视觉语义及代表性文案，取得用户认可后实现；
最终按目标读者完整任务试用验收。未获样板及推广范围认可，不批量复制。

使用 $math-storytelling（skills/math-storytelling/SKILL.md）设计核心问题、
已学→新增→用途、灵活叙事阶段表、简单到一般的推导及证明责任。
使用 $interactive-pedagogy（skills/interactive-pedagogy/SKILL.md）为关键概念
写六问交互规格，落实预测→操作→观察→解释，提供针对性错误反馈、递进提示和复位。
至少两个探索场景、两个误区/限制、一个改变条件或表示的迁移挑战、2–4 道理解题、
3–5 条总结及已注册相关链接；纯本地课按任务卡在本地落实主动探索。

编写课程内容前，先检查 math-storytelling、interactive-pedagogy、humanizer-zh、
ui-ux-pro-max 的实际 SKILL.md 与必要资源。缺失、不可读或不完整时，暂停课程内容编写，

阶段 3 必须使用 ui-ux-pro-max，按当前 Svelte 技术栈检查具体交互、响应式与无障碍，
沿用项目组件与主题；阶段 4 必须使用 humanizer-zh，以中性自然中文润色并复核数学含义。
不自动安装，不降级替代，不把通用 humanizer 当成 humanizer-zh。
保留课程身份/路由/正式前置与公共接口，超范围需求记录，不夹带其他课程或新依赖。
按项目要求运行检查，浏览器变更验证指定课程并附截图或操作证据。
最后报告课程 ID、交互、数学核对、实际检查结果、主题/响应式/链接/范围、文件清单及限制。
```
