# 贡献指南

开始前读取根目录 AGENTS、ARCHITECTURE、LESSON_SPEC、任务卡与组件文档。LESSON_SPEC 是教学验收标准；任务卡补充本课具体设计，类型与校验脚本提供最低结构门槛。

## 分支与 PR

所有课程、文档和基础设施更新都通过 PR 合并到 `main`，不直接推送 main。遵循 Conventional Commits；使用 Create a merge commit，保留分支提交与合并节点，让 Git 历史呈现分支开发和 PR 合并的关系。仓库仅启用 merge commit，禁用 squash merge 和 rebase merge；命令行使用 `gh pr merge --merge`，自动合并也选择 merge commit。

| 类型                       | 分支与范围                                                                                                                       |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 新建课程                   | `lesson/<ID>-<slug>`；每节课一个 PR，只改 `src/lessons/<ID>/**`、`labs/lessons/<ID>/**`                                          |
| 既有课程批量修订           | 经用户授权使用 `codex/<topic>` 单分支/单 PR，列出课程 ID、范围和逐课验证；可包含直接相关的共享代码、前置关系、约束文档与生成结果 |
| 公共组件、类型、依赖、构建 | 非批量修订时使用独立基础设施分支/PR，先保证旧课程兼容                                                                            |
| 规范、共享文档、任务卡生成 | 非批量修订时使用独立 `docs/<topic>` PR；生成器与其生成文档在同一 PR 更新                                                         |

新建课程使用独立分支，一课一 PR；这项限制不适用于既有课程的授权批量修订。批量修订须围绕同一问题或一致的验收标准，PR 列明所有受影响课程及共享改动，并逐课完成教学与数学检查；不得夹带新课程、无关改动或全局格式化。多个 Agent 并行开发时仍各用独立 worktree，不共享可写工作目录；一个文件同一时间只有一个所有者。提交示例：`feat(M03-010): add deterministic gradient descent experiment`。

## 检查与合并

1. 按 LESSON_SPEC 完成教学、数学与交互自查；通过类型、格式、lint、课程校验、相关测试和生产构建。
2. 对比 `origin/main` 检查授权范围；`pnpm scope:check` 对新建课程的课程命名分支执行目录限制，可通过 `SCOPE_BASE` 指定基线。`codex/<topic>` 批量分支仍需对照授权课程清单检查完整差异，不能把未触发单课目录门禁当作范围验收。
3. 创建以 main 为目标的 PR，按模板列出结果、数学证据、实际检查、截图/交互说明、限制和修改文件。
4. 等待 PR CI 全部通过，再审阅教学、数学、完整任务与文件范围。课程/运行时变更还须维护者绑定当前提交确认 `teaching-review`；样板额外满足 TEACHING_DESIGN 的设计批准、目标读者试用及用户接受。作者自查或模型报告不能代替人工判断。
5. 若基线变化，更新分支、解决冲突并重跑受影响检查。由维护者或明确获授权的 Agent 合并，禁止绕过失败检查或强制覆盖 main。
6. 合并后核对 main 的部署工作流；未成功部署时不能报告已经上线。完成后可删除已合并的任务分支，保留 PR 记录。

文档 PR 同样需要 CI 和内容一致性审阅；不相关的 UI/数学/硬件验证可标明不适用，不虚构执行结果。仅在调整教学/运行时合同确有必要时安排代码变更；与同一批量修订直接相关时可合入同一 PR。

### 人工教学验收与合并门禁

`Teaching review` 工作流针对 `src/`、`labs/`、`curriculum/` 下的任何变更要求人工验收，涵盖共享界面及设计源，宁可多审而不静默漏审。纯规范/工具 PR 自动标记不适用。它使用 PR 文件列表和评论发布提交状态 `teaching-review`，不分析文风、不证明学习效果，也不将 ready 状态视为验收结论。

维护者在当前 PR 发表独立评论，第一行严格使用完整 head SHA，第二行起写实际验收记录或其链接：

```text
/teaching-accept <当前 PR 的完整 head SHA>
课程 ID、设计确认位置、试用前置知识、任务结果、卡点与复验、证据链接及已知限制。
```

仅 GitHub 判定为 OWNER/MEMBER/COLLABORATOR 的非 Bot 账号记录有效。允许单维护者仓库的 PR 作者本人确认，但必须是人类真实决定；Agent 不得代发该命令、勾选人工接受或借维护者账号自我批准。账号类型只能排除已标记机器人，无法证明键盘前是人类，这仍是维护责任。对工具/运行时但不涉及教学的变更，可写实际影响核查和教学试用不适用理由，不编造试用。

每次新提交都需要重新验收；编辑为非接受评论或删除有效评论撤回该记录，删除全部有效记录后恢复失败。评论创建/修改/删除均重新读取 PR 当前提交。API 错误不得放行；取得 head 后先置 pending，避免接口故障沿用成功结果。其他有效同提交记录仍存在时保持接受。样板身份和推广授权由用户另行明确，不由该命令自动授予。

该高权限工作流只执行目标分支/default branch 上的脚本，不检出 PR head、不安装 PR 依赖；只授予读取及提交状态写权限。不要将其改为运行不可信 PR 代码。工作流首次进入 main 后才会对后续 PR 生效；引入它的 PR 仍需手工审阅。

**远端启用要求**：合并本流程后，在默认分支 ruleset 中保留已有防删除/防强推规则，增加必须通过 PR、必须通过当前实际 CI 检查及 `teaching-review`，并禁止绕过。启用前先让新工作流运行一次，核对 PR 的实际检查名，不猜测 reusable workflow 的前缀。要求最新基线时启用 strict；批准绑定 SHA 已由上述脚本实现。单维护者场景不强制另一位 GitHub reviewer，否则无法正常合并；多人项目可另外要求独立批准。

本轮读取到远端 default ruleset 只有防删除和防强推，未要求 PR 或检查；本地工作流不能自行使远端规则生效。不要在新状态尚未部署时先设置为 required，避免锁住引入流程的 PR。部署与 ruleset 激活由维护者在本 PR 合并后完成，未核对远端状态前不得声称已有强制合并保护。

## 课程目录与任务卡

课程身份由维护者预注册，实现通过 glob 自动发现，单课 Agent 无需修改全局注册表。
ID 永久且不复用；维护者新增身份时选用唯一 slug 并校验 DAG。

修改 `curriculum/designs` 或任务卡生成模板后运行 `pnpm tasks:generate`，目录变更运行 `pnpm docs:generate`，提交生成结果并运行 `tasks:check` / `docs:check`。不直接修改生成任务卡。设计源列出的误区是必讲项，课程仍需满足 LESSON_SPEC 的至少两个误区。

## 并行工作

Agent 只需标准协议、任务卡与组件文档，不以阅读全项目为前提。公共能力不足先做课内组件，复用能力在 PR 记录；新建课程走独立基础设施任务，授权批量修订可在同一 PR 内处理直接相关共享改动。
冻结合同后，破坏性接口变更需显式版本迁移和受影响课程验证。Phase 1 完成前不开展大量课程并行。

## CI 课程遍历范围

PR 按目标分支与当前提交的 merge-base 计算差异；main push 按事件 before/after 比较，覆盖本次推送的全部提交。课程目录或本地实验目录变更只检查对应课程。注册表新增或修改只检查相关课程；删除实现检查 planned 回退，删除身份或修改 slug 检查旧地址的 404 行为。无法获得有效基线时失败，不自动全量或静默跳过。手动部署必须填写 baseline 提交 SHA。

浏览器任务按变更决定是否执行：仅 `skills/**/*.md`、`docs/**/*.md`、根目录 `README.md` / `AGENTS.md` / `PLAN.md` 或 PR 模板变更时跳过浏览器，所有质量检查和生产构建仍执行。课程目录中的说明文档不在豁免范围内；其他路径、未知路径及混合变更保守运行浏览器。新增、删除与重命名都参与判断，差异基线无法确定仍失败。工作流始终触发，只跳过 browser 任务，避免必需检查悬空。

为 PR 添加 `ci:e2e` 标签可强制运行现有浏览器回归；添加或移除标签都会重新判断，标签保留期间的新提交也会继续加测。标签不扩大课程遍历范围；全量遍历仍使用 `audit-courses-v*` tag。手动部署始终运行浏览器回归。main push 复用同一自动规则；Pages 构建与部署保持原样。

需要运行浏览器时，日常 CI 保留固定的核心交互、进度、代表性 ready/planned 页面、主题、横屏桌面和离线回归；完全移除窄屏、竖屏及手机布局回归，不保留 320px 阅读降级验收。默认视口为 1280×720，布局场景另查 1920×1080；保留桌面缩放与键盘验证。共享组件、路由、依赖等变更不触发全量课程遍历；未改课程的特有回归可能延迟到全量审计发现。CI 只安装和运行 Chromium：project base 运行固定回归与选中课程，root base 只运行固定冒烟。无课程变更时课程遍历明确跳过。成功和失败均保留 Playwright 报告及 test-results 7 天，PR 中长期验收证据需附可持久访问的位置。Firefox/WebKit 可本地手动运行；CI 不覆盖其特有兼容性。

只有推送匹配 `audit-courses-v*` 的 tag 才触发全量课程遍历，例如 `audit-courses-v2026.10.21.1`。审计校验 tag 指向的提交，只运行 CI，不部署 Pages；由维护者在需要全量回归时创建并推送 tag，普通 main 发布不触发全量。CI 日志显示模式、基线和选中课程 ID。

本地 `pnpm test:e2e` 默认仅运行固定回归；测试选定课程时，通过 `LESSON_SELECTION` 传入 JSON：`{"lessons":[{"id":"M01-002","slug":"math/linear-algebra/vector-addition","title":"向量加法与数乘"}],"removed":[]}`。课程 ID、slug 与标题以注册表为准，`removed` 为需要验证 404 的旧地址记录。
