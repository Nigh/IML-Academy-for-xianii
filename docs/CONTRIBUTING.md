# 贡献指南

开始前读取根目录 AGENTS、ARCHITECTURE、LESSON_SPEC、任务卡与组件文档。LESSON_SPEC 是教学验收标准；任务卡补充本课具体设计，类型与校验脚本提供最低结构门槛。

## 分支与 PR

所有课程、文档和基础设施更新都通过 PR 合并到 `main`，不直接推送 main。遵循 Conventional Commits；默认 squash merge，使每个 PR 对应一个可追踪提交。

| 类型                       | 分支与范围                                                                              |
| -------------------------- | --------------------------------------------------------------------------------------- |
| 单课实现或修订             | `lesson/<ID>-<slug>`；每节课一个 PR，只改 `src/lessons/<ID>/**`、`labs/lessons/<ID>/**` |
| 公共组件、类型、依赖、构建 | 独立基础设施分支/PR，先保证旧课程兼容                                                   |
| 规范、共享文档、任务卡生成 | 独立 `docs/<topic>` PR；生成器与其生成文档在同一 PR 更新                                |

单课使用独立分支；多个 Agent 并行开发时各用独立 worktree，不共享可写工作目录。一个文件同一时间只有一个所有者。禁止多课捆绑、无关改动或全局格式化。提交示例：`feat(M03-010): add deterministic gradient descent experiment`。

## 检查与合并

1. 按 LESSON_SPEC 完成教学、数学与交互自查；通过类型、格式、lint、课程校验、相关测试和生产构建。
2. 对比 `origin/main` 检查授权范围；`pnpm scope:check` 对课程命名分支执行目录限制，可通过 `SCOPE_BASE` 指定基线。
3. 创建以 main 为目标的 PR，按模板列出结果、数学证据、实际检查、截图/交互说明、限制和修改文件。
4. 等待 PR CI 的全部检查通过，再审阅教学内容、数学条件、2–4 道理解题、至少两个误区，以及文件所有权；自动检查不能替代内容审阅。
5. 若基线变化，更新分支、解决冲突并重跑受影响检查。由维护者或明确获授权的 Agent 合并，禁止绕过失败检查或强制覆盖 main。
6. 合并后核对 main 的部署工作流；未成功部署时不能报告已经上线。完成后可删除已合并的任务分支，保留 PR 记录。

文档 PR 同样需要 CI 和内容一致性审阅；不相关的 UI/数学/硬件验证可标明不适用，不虚构执行结果。仅在调整教学/运行时合同确有必要时安排独立代码变更。

## 课程目录与任务卡

课程身份由维护者预注册，实现通过 glob 自动发现，单课 Agent 无需修改全局注册表。
ID 永久且不复用；维护者新增身份时选用唯一 slug 并校验 DAG。

修改 `curriculum/designs` 或任务卡生成模板后运行 `pnpm tasks:generate`，目录变更运行 `pnpm docs:generate`，提交生成结果并运行 `tasks:check` / `docs:check`。不直接修改生成任务卡。设计源列出的误区是必讲项，课程仍需满足 LESSON_SPEC 的至少两个误区。

## 并行工作

Agent 只需标准协议、任务卡与组件文档，不以阅读全项目为前提。公共能力不足先做课内组件，复用能力在 PR 记录并走独立基础设施任务。
冻结合同后，破坏性接口变更需显式版本迁移和受影响课程验证。Phase 1 完成前不开展大量课程并行。
