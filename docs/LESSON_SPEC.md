# LESSON_SPEC — 交互课程统一开发规范 v1

本规范定义单课的教学与交付标准；公共类型以 `src/lib/lesson/contract.ts` 为准。v1 接口已通过 Phase 1 的 PR CI 与代理内容审阅并冻结；后续破坏性变更需显式迁移。

问题驱动叙事、主动探索和迁移挑战的设计与审阅，另见 [教学设计质量规范](TEACHING_DESIGN.md) 和 [单课优化流程](LESSON_OPTIMIZATION.md)。两者补充本规范，不改变公共接口或降低下述教学要求；[Skills 协作说明](TEACHING_SKILLS.md) 提供调用与移植方式。

## 1. 职责、输入与文件所有权

课程 Agent 负责一节在其正式前置知识基础上可完整理解、数学严谨、交互充分的课程。开始前依次读取：

1. 根目录 `AGENTS.md`。
2. `docs/ARCHITECTURE.md` 与本规范。
3. `curriculum/tasks/<LESSON_ID>.md`。
4. `docs/COMPONENTS.md`、`docs/NOTATION.md`；有本地实验时读取 `docs/LOCAL_LABS.md`。

无需阅读其他课程的实现。任务卡补充本课具体要求，不能降低本规范的教学底线；发现公式、前置关系或接口冲突时，在 PR 中记录，由维护者处理。

新建课程任务的默认可写范围只有：

```text
src/lessons/<LESSON_ID>/**
labs/lessons/<LESSON_ID>/**
```

新建课程不得修改其他课程、curriculum 清单、App、路由、共享组件、构建系统、依赖或根配置。共享能力不足时优先做课内专用实现，并在 PR 中记录可复用能力需求；公共变更走独立基础设施 PR。

既有课程的授权批量修订不受“一课一 PR”限制：使用一个批量分支和一个 PR，可包含授权课程及直接相关的共享代码、先修规划、约束文档和生成结果；须列明范围与逐课验证，不能夹带新课程。文件所有权与 CI/教学/数学验收要求不变，详见 CONTRIBUTING。

## 2. 目标读者与教学结构

课程面向有工程兴趣的读者，以高三数学为全课程入口，不默认学过线性代数、微积分或大学概率论。随着课程推进，数学起点沿正式前置关系累积提升；EE背景用于选择自然案例，不作为省略数学解释的理由。中文为主，保留英文术语。

- **已学**：正式前置课程已经充分讲解并有理解检验的知识。开头简短回顾并链接，后续直接应用，不每课从高中重新讲起。
- **本课新增**：首次需要的新概念，正文解释用途、直觉、定义、手算示例、符号和成立条件，再引导预测、操作与解释。不能用未解释概念定义另一个概念。
- **补充**：只提过名称、折叠进阶内容或外部阅读不等于已掌握，不得悄悄成为后课核心前提。若后课必需，应正式教学或调整前置关系。
- 每课记录“已学知识 → 本课新增 → 后续用途”；课程编号不是先修证明。发现缺口先补课内解释，确有课程依赖时由规划维护任务处理并验证DAG；与授权批量修订直接相关的规划可纳入同一PR。
- 核心知识直接展开，一般化证明与实现细节可折叠。篇幅不足的必要补课说明具体知识、掌握目标和可访问学习入口，不只说“请先学线性代数”。
- 教学审阅以“具备高中数学并完成正式前置课程”的读者为准，要求能解释例子、预测参数后果、说明反例；结构检查不证明理解。

从直觉和问题出发，建立模型，再用交互验证，最后讨论应用与限制。直觉 → 实验 → 推导或直觉 → 模型 → 实验均可，按最自然的理解顺序组织。

Shell 已提供标题、模块、难度、时间、目标、前置、状态、测验、进度和导航。正文不重复创建 h1 或自行保存进度，可合并章节，但必须覆盖以下内容：

| 内容       | 最低要求                                                                                             |
| ---------- | ---------------------------------------------------------------------------------------------------- |
| 动机       | 一个自然的实际问题；可用传感器、噪声、延迟、控制、机器人或训练评测案例，不强行关联硬件               |
| 直觉       | 解释解决什么问题，用图示说明变量、关系和变化趋势                                                     |
| 数学       | 标准公式、全部变量的含义/形状/单位、假设和适用条件；按难度给出推导，避免堆公式                       |
| 核心实验   | 至少一个有教学意义的交互，明确输入、算法、输出与观察目标；仅任务卡明确规定纯本地实验时豁免浏览器交互 |
| 参数探索   | 至少两个有意义的正常、边界、不稳定、极端或反直觉场景，尽量提供一键预设                               |
| 误区与限制 | 至少两个误区、反例、限制或失败案例，并解释原因                                                       |
| 理解测试   | 2–4 道检查结果预测、参数后果、公式含义、成立条件或工程应用的问题，不仅考术语记忆                     |
| 总结       | 3–5 个核心结论，并链接已注册的相关课程；不得引用不存在的页面                                         |
| 本地实践   | 如适用，完整提供环境、数据、代码、执行与结果检查方法，见第 6 节                                      |

## 3. 课程文件与接口

```text
src/lessons/M03-010/
  lesson.ts
  Lesson.svelte
  experiment.ts
  experiment.test.ts
  lesson.test.ts
labs/lessons/M03-010/     # 仅有本地实验时
```

`lesson.ts` 默认导出 `LessonDefinition`，包含 `id`、`contractVersion: 1`、`status`、`sections`、`quiz` 和可选 `localLab`。从 draft 开始，达到完整验收标准后再声明 ready。

```ts
import type { LessonDefinition } from '../../lib/lesson/contract';
export default {
  id: 'M03-010',
  contractVersion: 1,
  status: 'draft',
  sections: [{ id: 'motivation', title: '为什么要优化' }],
  quiz: [],
} satisfies LessonDefinition;
```

这是允许逐步开发的 draft 接口示例，不能作为 ready 内容提交。章节 ID 在课内唯一，使用英文短横线，与正文 `TheorySection` 的 id 一致。ready 的结构检查至少要求五个实际章节。

`Lesson.svelte` 默认导出接受只读 `metadata: LessonMetadata` 的组件，复用类型和章节组件：

```svelte
<script lang="ts">
  import type { LessonBodyProps } from '../../lib/lesson/contract';
  import TheorySection from '../../components/lesson/TheorySection.svelte';
  let { metadata }: LessonBodyProps = $props();
</script>

<TheorySection id="motivation" title="为什么要优化">
  <p>{metadata.title}的工程动机、可验证模型和解释写在这里。</p>
</TheorySection>
```

每道单选题使用稳定的问题/选项 ID、版本、题干、选项及正确答案 ID；正确项与每个干扰项都需解释：

```ts
{
  id: 'step-direction', version: 1,
  prompt: '问题文本',
  options: [
    { id: 'a', text: '选项 A', explanation: '为何对或错' },
    { id: 'b', text: '选项 B', explanation: '为何对或错' },
  ],
  answerId: 'a',
}
```

题意或答案含义改变时增加 version。首版单选，无需服务端保密答案。完成状态由用户确认，不要求测验满分；planned/draft 不能标记完成。

## 4. 交互与界面

- Svelte 5、TypeScript strict；优先使用已实现的公共组件，不能假设 Phase 1 待建组件已经存在，也不复制多套近似 UI。
- 遵守 Xianii Tokens、字号与间距规范，兼容亮暗主题；不得为单课修改全局设计系统。
- 参数变化尽量即时反映到真实数学计算结果；同时展示过程和关键中间量，不只给最终答案。
- 参数标明名称、单位、默认值、范围和无效输入反馈，支持复位与键盘操作；不能只支持拖动。
- 图表有轴标签、单位、图例及必要的文字说明，重要信息不用颜色单独区分。SVG 或 Canvas 正确处理高 DPI 与屏幕缩放。
- 横屏桌面支持范围：项目不为窄屏、竖屏提供适配，也不验收窄屏阅读或降级页面。建议在 720p 及以上横屏中使用；自动验收以 1280×720 CSS px、100% 缩放为最低视口，另查 1920×1080。这里指浏览器可用视口，不是显示器物理分辨率。图形、核心参数与主要反馈组成同一工作区；进入工作区后，调整与观察不应要求上下往返滚动。必要时减少同时呈现的控制项或分阶段操作，不以缩小字号解决。
- 窄屏、竖屏和手机触屏不在适配与测试范围内，不要求新增降级视图或拦截页面。保留桌面键盘、高 DPI 和缩放支持，不得禁用浏览器缩放。桌面 200% 缩放时允许重排和滚动，但参数、结果、错误和键盘路径必须可达且不被遮挡；这不构成窄屏适配承诺。
- 视觉编码按对象含义分配：实际路径、合位移、目标/辅助线各有稳定表达。两段实际移动使用一致的路径线型，以编号、直接标签或端点标记区分；不能仅为满足“非颜色区分”把第二段改成虚线。虚线等样式须有明确语义，合位移不能与实际路线混淆。共享图表默认样式不能覆盖本课含义。
- 不用装饰性动画，尊重 reduced motion。长运算限制样本数、迭代数或耗时，避免阻塞页面。
- 逐步算法提供初值、步号、状态、单步、播放/暂停、速度和复位；隐藏页暂停，卸载清理动画、计时器与订阅。
- M01-002 的用户及格基线（`6d767aa`）已完成实际试用，具体可复用要求与推广授权见 TEACHING_DESIGN。新修订不得恢复核心交互分离、全课窄正文、未执行就出现的位移箭头或改参后残留的执行图形。应验证开始、运行、完成、重试与复位，不以默认截图替代完整状态转换；物理等价关系应有明确的操作对照与文字解释。

共享组件的实际 props 见 COMPONENTS；复杂的课程专用可视化留在课内目录。

### 4.1 预设图形的可读性验收

默认状态、每个一键预设和复位后的图形都必须直接表达该场景的教学关系，不能要求读者先拖动、缩放或猜测标签。以下要求也适用于既有课程的后续修订；本次文档更新不代表既有预设已经优化或验收。

- **先定观察目标，再选数值与视域**：预设说明写明要比较的方向、夹角、投影、分布差异或收敛行为。选择能显著呈现该关系的参数和坐标范围，不能机械沿用覆盖全部输入上限的大范围，让非退化内容挤在原点附近。常规预设的主要几何跨度宜占对应绘图区可用跨度的 40%–80%，作为布局起点而非数学硬阈值；不满足时需说明教学原因并提供清晰的替代呈现。
- **留出完整边界**：视域包含原点（教学需要时）、所有关键端点、投影落点、轨迹和参考线，并为箭头、标记与标签留白。向量长度与夹角比较必须保持等比例坐标。跨预设比较若改变坐标尺度，需明确提示，不能让独立缩放造成大小或变化幅度的误读。
- **分开标签与图形**：原点刻度、向量名、投影名、角度和数值不得互相遮挡，也不得压住关键箭头、线段或被边缘裁切。优先调整预设、视域、标签位置或使用引线；空间不足时把详细数值移到带对应标识的图例/结果区。不得通过缩小到字号规范以下解决拥挤。
- **如实表达退化场景**：零向量、正交时的零投影、重合点或接近平行等情况可能天然拥挤。保留真实数值和重合关系，使用独立文字说明、引线或明确标注尺度的局部放大；不得给数据加偏移或伪造非零长度。一般输入不必全部自动适配，但必须有可读的边界说明和数值结果。
- **逐个检查，留下证据**：对默认值、全部预设、连续切换和复位逐一检查；覆盖亮/暗主题、上述两个横屏桌面视口和桌面 200% 缩放。完全移除 320px 等窄屏及竖屏验收，不为其生成截图或保留测试项目。支持范围内复杂图可局部滚动，页面不得整体溢出；缩放时可按上述规则重排和滚动。PR 列出预设、观察目标、参数/视域与检查结果，附能辨认标签的截图和一次完整核心任务操作记录；仅数据/组件断言通过不能证明布局可读。

例如，投影预设若让 a、b、proj 与 0 全部堆在原点附近，即使数学结果正确也不通过验收。应先收紧视域或选用保持目标关系且尺度合适的参数，再处理标签；零投影预设则明确说明投影落在原点，并将标签移到可读位置。

## 5. 数学计算与质量底线

复杂计算与 UI 分离，`experiment.ts` 导出纯函数和类型。纯本地实验可在其中放实际的数据/配置/结果校验逻辑，不伪造网页训练，也不放空测试凑文件。

| 类型       | 实现与验证要求                                                                                              |
| ---------- | ----------------------------------------------------------------------------------------------------------- |
| 确定性算法 | 对照解析解、标准算法或可信参考实现，断言结果/不变量，检查边界和无效输入；浮点容差结合尺度说明               |
| 随机模拟   | 明确 seed 与样本数，允许重新采样；默认固定基础随机样本比较参数影响，解释波动和统计局限                      |
| 数值优化   | 明确初始值、学习率等参数、迭代数与终止条件；解释收敛/发散，限制运行次数并处理 NaN、Infinity、溢出及非法参数 |

公式采用 KaTeX，符号遵循 NOTATION。所有近似、经验统计和预计算结果明确标注。引用外部结论或性能数字时说明来源、条件和测量方法。

禁止：纯长文或装饰图替代必要交互；伪随机图形冒充模型结果；直接复制教程；省略模型条件；混淆相关与因果、训练误差与泛化误差；把预测当物理真值；无来源的绝对性能声明；网页暗中调用外部 AI API。

## 6. 本地实验

真实模型训练、Python/PyTorch、GPU、MuJoCo 或设备任务在用户自行管理的本地环境执行，网页只提供教程和参考代码。

必须包含：目标与前置、支持环境和依赖安装命令、数据来源/格式、可独立运行代码、执行步骤、输出检查方法、合理结果范围、排错及进一步实验。说明 seed、软件版本与硬件差异，不声称用户已运行代码，也不报告未执行的实测结果。

`lesson.ts` 的 `localLab` 描述 `environment`、`data`、`steps`、`files`、`expected`、`troubleshooting`。文件相对 `labs/lessons/<ID>`，禁止越界，每个不超过 1 MiB；构建复制到 `BASE_URL + labs/<ID>/<file>`。优先 `.py`，不提交模型权重、敏感数据或受限数据集。完整要求见 LOCAL_LABS。

## 7. 验收与 PR 交付

结构校验是最低自动门槛，不替代教学审阅：当前 schema 只检查 ready 至少有一道有效题；本规范要求的 2–4 题和至少两个误区由内容审阅确认。既有课程下次更新时按本规范补齐，本次规范更新不追溯修改课程实现。

提交前逐项确认：

1. `pnpm check`、`pnpm lint`、`pnpm format:check` 通过。
2. 相关数学与组件测试通过；`experiment.test.ts` 覆盖任务卡场景、解析值/不变量、边界、非法输入和适用的随机复现；`lesson.test.ts` 覆盖协议、章节、参数变化、复位与主要交互。
3. `pnpm validate:curriculum`、`pnpm validate:lessons`、`pnpm build` 通过，PR CI 全部通过。
4. 按第 4.1 节逐个验收默认值、全部预设与复位图形；实际检查主要交互、键盘、亮暗主题、重要响应式布局和缩放；涉及页面/交互/存储变更时运行 Playwright，记录截图或操作说明。
5. 相关链接均指向已注册课程；本地参考文件存在且路径正确。
6. 对比 main 检查变更仅在授权目录，没有无关课程或全局格式化修改。
7. 教学结构、2–4 道题、至少两个误区及数学正确性经过审阅；不以字段声明或空测试获得 ready。按 TEACHING_DESIGN 检查失败条件，样板须人工确认设计稿并完成目标读者试用。CI 仅核对技术结果与人工审阅记录，不能判断文案自然或学生已理解；ready 不自动授予样板资格。

新建课程使用独立 `lesson/<ID>-<slug>` 分支，一课一 PR，目标为 `main`；禁止捆绑新课程或直接推送 main。既有课程可按授权范围使用一个 `codex/<topic>` 分支和一个批量修订 PR，并纳入直接相关的共享基础设施、先修规划和文档更新；其他公共维护仍独立提交。使用 Conventional Commits；通过 CI 和内容审阅后合并，不能绕过失败检查。具体合并流程见 CONTRIBUTING。

完成报告及 PR 必须列出：课程 ID、实际交互、数学验证方式、实际运行的测试与结果、主题/响应式/链接与文件范围检查、限制和遗留问题、修改文件清单。未运行的验证明确注明。

## 8. Phase 1 交互组件实现约定

`Interactive Component Contract v1` 的真实接口与限制见 [COMPONENTS](COMPONENTS.md)，
三种完整 Svelte 组合示例见 [INTERACTIVE_GUIDE](INTERACTIVE_GUIDE.md)。
当前共享 Plot2D、VectorDiagram、DistributionPlot、HistogramPlot、ContourPlot、MatrixView、
预设、算法解释与播放组件均有实际实现。不得复制另一套公共控件或在课程中修改其 API。

实验状态由课程持有，派生数学结果使用纯函数与 `$derived`。
SimulationControls 仅推进时间/索引；StepByStep 仅显示解释步骤，二者不代替数学模型。
模型参数变化须重置迭代，并停止先前播放（可以使用 key 重建控制器）。
